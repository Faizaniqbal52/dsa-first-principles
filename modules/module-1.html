2 The story · why strings exist

The computer only knows numbers. So how does it remember a word?

Your array holds numbers: marks, ages, prices. Lockers hold numbers. That's all a computer can physically store, tiny numbers in numbered lockers.

Now the school asks for one more thing: store each student's name.

A name like AMY is letters, not numbers. A locker can't hold the letter A. So what do you do? Pick whatever feels natural.

Reasonable, but noThe hardware can't change. A memory locker holds a number, full stop. We can't build a "letter locker". So we have to be cleverer with the numbers we already have.
That's the oneExactly what humans did. If everyone agrees that a certain number means a certain letter, then storing letters becomes storing numbers, and you already know how to store numbers.
Honest answerNo problem. The trick is simple once you see it: don't store letters at all. Store numbers that everyone agrees stand for letters.

In the 1960s, people sat down and agreed on a shared codebook. It's called ASCII. It just says which number means which letter:

The codebook · a tiny piece of ASCII
A = 65    B = 66    C = 67    …    Y = 89    Z = 90
a = 97    b = 98    …    space = 32    ! = 33    0 = 48
So the name AMY is really just three numbers: 65, 77, 89. And three numbers in a row is something you already know how to store.

A word is a row of these letter-numbers, side by side.

Wait. A row of numbers, side by side, found by position? That's an array. You didn't need a new idea at all. A string is just an array whose values happen to be letter-codes.

3 The idea · string = array of characters

A character is a number. A string is an array of them.

Here's the whole module in one line: a string is an array of characters, and a character is just a small number from the codebook.

New word · Character A single letter, digit, space, or symbol. Inside the machine it's stored as its codebook number. In C++ the type is char, and one char is one small number.
New word · String A row of characters, side by side, found by position, exactly like an array. name[0] is the first letter. In C++ the type is string.

YesA string is an array, so position 0 is the first item, which is the character 'A'. And 'A' is really the number 65 under the hood.
Not quite. Remember, a string is an array of characters, and arrays start at position 0. What sits at position 0 of "AMY"? Try again.

The handy trick · c - 'a' Since letters are numbers, you can do maths on them. 'c' - 'a' is 99 minus 97, which is 2, so 'c' is the 2nd letter (counting from 0). This tiny trick turns any lowercase letter into a position from 0 to 25. You'll use it constantly.
✦ Bonus · go deeper, optional

Still curious? Keep asking why

Optional, as before. Press why? to open each reason. Skip it and come back whenever.

Uppercase 'A' and lowercase 'a' are different numbers.

They have to be, or the computer couldn't tell them apart. 'A' is 65 and 'a' is 97. Notice they're exactly 32 apart. That gap is the same for every letter, which is why "make it lowercase" is really just "add 32".

Letters don't start at 0. 'A' is 65.

The first 32 codes (0 to 31) were saved for control signals, not printable text, things like "new line" and "tab" and the old "ring the bell". Then space is 32, digits are 48 to 57, and capital letters begin at 65. It's a historical layout, but once everyone agreed on it, it stuck forever.

One emoji can take several lockers.

ASCII only had room for English. The world has far more symbols than fit in one small number, so a bigger codebook called Unicode took over, and a scheme called UTF-8 stores each symbol in one to four lockers. So "length" gets tricky: what looks like one emoji on screen might be four characters in memory. For a-z problems you can ignore this, but it's why counting characters in real text is harder than it looks.

5 Where it hurts · the string traps

Same array, same weaknesses, plus one nasty trap

Because a string is an array, it inherits every array weakness: inserting or deleting in the middle shifts everyone (O(n)), and searching for a value means checking every locker (O(n)). But strings add one trap that catches almost every beginner.

The concatenation trap

Building a big string by adding one piece at a time, inside a loop, can quietly cost O(n²). Each "add" may copy the whole string so far to a bigger spot. A thousand adds means copying again and again.

Insert or delete in the middle

Removing a character from the front shifts every other character left. Same no-gaps rule as arrays, same O(n) cost.

Copies feel free but aren't

Passing a big string around by value copies all of it. In C++, pass by reference (string&) when you can, to skip the copy.
Quick check
You build a huge string by doing result += piece a million times in a loop. What's the danger?
RightThis is the classic string trap. Each += may have to copy everything built so far into a bigger space. Reserve space up front, or build into one buffer, and it drops back to O(n).
Think back to how arrays grow: when they run out of room, they copy everything to a bigger row. Now imagine that happening on every add. Try again.

6 Daily life · strings are everywhere

Where strings hide in your day

Every message you send

A text is a string of characters. Autocorrect, character counts, and "seen at 9:41" are all string work.

Search boxes

"Does this product name contain what I typed?" is a string scan, done millions of times a second.

Web addresses

A URL is a string the browser slices into pieces: the site, the path, the query. All position and substring work.

Passwords

Strength rules ("has a digit, has a symbol") are just scans over the characters, counting what's there.

DNA

Biologists store genomes as strings over just four letters, A C G T, and run string algorithms to find patterns.

Code itself

The program you write is a string. The compiler reads it character by character before it ever runs.

7 Practice · think first

Spot the string pattern

Three real situations. As before, the hints are questions, not answers. Try each in your head before opening the next. Notice how often the answer is "two pointers" or "count the characters".

Problem 1 · warm-up
A chat app has a "reverse text" party trick: type a word, it shows it backwards. You must reverse the characters without using extra memory for a second copy.
Lead your own thinking
Hint 1 · what is the data?A word is a row of characters. What did you use in the Spotify and Move Zeroes problems to walk a row from both ends?
Hint 2 · the moveWhat if you swapped the first and last characters, then the second and second-to-last, working inward?
Hint 3 · when do you stop?The two pointers move toward each other. When they meet in the middle, what's left to do?
Discussion

Put one pointer at the start and one at the end. Swap them, then step both inward. Stop when they meet. No second copy needed, so O(1) extra space. This is the exact same two-pointer wall you used on Spotify and Move Zeroes, now on characters. The pattern travels across topics.

Problem 2 · the counting trick
A spam team wants to catch impersonators who just shuffle letters, like netflix and flintex. Given two usernames, decide fast if one is an anagram of the other (same letters, same counts).
Lead your own thinking
Hint 1 · what makes them anagrams?Forget order. What has to be true about the counts of each letter in both words?
Hint 2 · the lazy planYou could sort both words and compare. That works. What does sorting cost, and is it more than you actually need?
Hint 3 · the c - 'a' trickYou only care about counts of 26 letters. Could you keep a tally in a small array of size 26, using c - 'a' as the position?
Hint 4 · one array, two passesAdd one for each letter of the first word, subtract one for each letter of the second. If everything ends at zero, what does that mean?
Discussion

Sorting works but costs O(n log n), and you don't need the order at all. You only need counts. Keep an array of 26 tallies. Add for the first word, subtract for the second. All zeros at the end means identical letter counts, so anagram. That's O(n), one pass each. Turning a character into an index with c - 'a' is a baby version of hashing, which you'll meet in full at hash maps.

Problem 3 · scan and remember
A typing game highlights the first letter in a word that never repeats. For swiss the answer is w. You need the first non-repeating character.
Lead your own thinking
Hint 1 · what do you need to know?To call a letter "non-repeating", what do you first have to know about every letter?
Hint 2 · count firstWhat if you did one pass to count how many times each letter appears (that size-26 array again)?
Hint 3 · then scanAfter counting, do a second pass in order. What's the first letter whose count is exactly 1?
Hint 4 · why two passes?Could you do it in one pass? Why does "first in order" force you to know all the counts before you answer?
Discussion

Two passes. First, count every letter into a size-26 array. Second, walk the word in order and return the first letter whose count is 1. You need all the counts before you can trust "non-repeating", which is why you can't finish in a single pass. Cost: O(n) time, O(1) space (26 slots). Count first, then decide is a pattern you'll reuse forever.

8 Now code it · C++, interview-style

Two string problems, same five-step method

Exactly the method from Module 0: understand, brute force, find the waste, pseudo-code, then code and cost. The problems change, the method doesn't.

Try each yourself first. Open a step only after a real attempt.

Easy · warm-upLeetCode 344 · Reverse String

Reverse a list of characters in place, using no second array.

Example: ['h','e','l','l','o'] becomes ['o','l','l','e','h']

Step 1 · Understand it

Input: a row of characters. Output: the same row, reversed, changed in place. No new array allowed. Edge cases: an empty string and a single character both come back unchanged.

Step 2 · Brute force first

Make a new array. Copy the characters into it back to front. Then copy that back over the original. It works, but it uses O(n) extra space, and the problem said in place. So we know what we need to beat.

Step 3 · Find the waste (and the trick)

You've reached for two pointers twice now. Same move here. Put left at the start and right at the end. Swap them, step both inward, and stop when they meet. The array reverses itself with no second copy.

Step 4 · Pseudo-code the good idea
Pseudo-code · two pointers
left = 0
right = last index
while left < right:
    swap s[left] and s[right]
    left = left + 1
    right = right - 1
Step 5 · Code it, then cost it
C++
void reverseString(vector<char>& s) {
    int left = 0, right = s.size() - 1;
    while (left < right) {
        swap(s[left], s[right]);
        left++;
        right--;
    }
}

Time: O(n), each character is touched once. Space: O(1), just two index variables.

Connects to: the same two-pointer wall as Move Zeroes and the Spotify shuffle. Three different problems, one pattern.

Easy → MediumLeetCode 242 · Valid Anagram

Given two lowercase strings, return true if one is an anagram of the other (same letters, same counts).

Example: "anagram" and "nagaram" → true.   "rat" and "car" → false.

Step 1 · Understand it

Two words are anagrams when they contain the exact same letters the exact same number of times, ignoring order. If the lengths differ, it's an instant no. We're told the letters are lowercase a to z.

Step 2 · Brute force first

Sort both words, then compare them letter by letter. If the sorted versions match, they're anagrams. It works. But sorting costs O(n log n), and we're doing more work than the question needs. We never actually cared about order.

Step 3 · Find the waste

We only need counts, not order. So keep an array of 26 tallies, one per letter. Add one for each letter of the first word, subtract one for each letter of the second. Use c - 'a' to turn a letter into its slot. If every tally is zero at the end, the letters matched exactly.

Step 4 · Pseudo-code the good idea
Pseudo-code · count into 26 slots
if lengths differ: return false
count = 26 zeros
for each letter c in word A: count[c - 'a'] += 1
for each letter c in word B: count[c - 'a'] -= 1
for each value v in count:
    if v is not 0: return false
return true
Step 5 · Code it, then cost it
C++
bool isAnagram(string a, string b) {
    if (a.size() != b.size()) return false;
    int count[26] = {0};
    for (char c : a) count[c - 'a']++;
    for (char c : b) count[c - 'a']--;
    for (int v : count) if (v != 0) return false;
    return true;
}

Time: O(n), one pass per word. Space: O(1), the count array is a fixed 26 slots no matter how long the words are.

Connects to: turning a key into an array position with c - 'a' is exactly the idea behind hash maps in Arc 1. You're meeting it early, on easy mode.
