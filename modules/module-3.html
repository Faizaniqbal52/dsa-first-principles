1 Start from what you know · Module 3

Two pointers & the sliding window

You've quietly used two pointers four times already: the Spotify shuffle, Move Zeroes, reversing a string, and rotating a grid. This module turns that instinct into two named tools you reach for on purpose.

👋
Good newsThere's no new data structure here. These are two techniques for walking an array you already understand. They exist to kill one specific waste, and once you see it, you can't unsee it.
Quick recap · The waste we're hunting Lots of problems ask about pairs ("two things that add up to X") or ranges ("the best stretch of days"). The obvious solution tries every pair or every range with nested loops, which is O(n²). On 100,000 items that's 10 billion steps. We can almost always do it in one pass.

Here comes the problem ↓

2 The story · the nested-loop wall

Checking every pair is 10 billion steps. There has to be a better way.

A buyer gives you a sorted list of house prices and a budget. They want two houses whose prices add up to exactly the budget.

Prices: 1, 2, 4, 7, 9, 11, 15. Budget: 11. Find a pair that sums to 11.

You could try every pair. But the list is already sorted, smallest to largest. Does that ordering let you avoid checking all of them? Pick whatever feels natural.

It works, butThat's the brute force, and it's fine for tiny lists. But it's O(n²): for every price you re-scan the whole list. On big inputs it falls over. And it completely ignores the gift you were handed: the list is sorted. Let's use that gift.
That's the moveExactly. Put one finger on the smallest price and one on the largest. Their sum tells you which way to move. Sorted order means every move is a sure thing, never a guess.
Honest answerNo problem. Here's the trick: put one finger at each end of the sorted list. If their sum is too big, you need a smaller number, so move the right finger left. If it's too small, move the left finger right. Watch it below.

The key insight: on a sorted list, the sum of the two ends tells you exactly which finger to move. Too big? The right end is the only thing you can shrink. Too small? The left end is the only thing you can grow. You never waste a move.

3 Technique one · two pointers, converging

Two pointers: start at both ends, squeeze inward

Put a left pointer at the smallest value and a right pointer at the largest. Look at their sum, then move exactly one pointer based on what you need. Press step and watch it hunt for the pair.

left + right = ?   (target 11)
Two lit lockers are the pointers. Each step compares their sum to the target and moves one pointer. No pair is ever checked twice.
Why it's O(n) Each step moves a pointer inward by one, and the two pointers only ever move toward each other. So together they take at most n steps before they meet. One pass, not n passes. That's the whole win: O(n²) becomes O(n).
Quick check
Left + right is bigger than the target. Which pointer do you move, and why?
RightThe sum is too big, so you need a smaller value. On a sorted list, stepping the right pointer left is the only move that shrinks the sum. That certainty is exactly what sorting buys you.
The sum is too big, so you want it smaller. On a sorted list, which end holds the value you can shrink? Try again.
⚠️
The one catchConverging two pointers relies on the list being sorted. Without an order, moving a pointer tells you nothing, so the trick falls apart. If the data isn't sorted, either sort it first (Module 9) or reach for a different tool (hash maps, Module 7).
4 Technique two · the sliding window

Sliding window: reuse the range instead of rebuilding it

Now a different pain. "What's the best stretch of k days?" The lazy way re-adds every window from scratch, which is O(n × k). But two neighbouring windows overlap almost entirely. So when the window slides one step right, just add the new value and subtract the one that fell off. Press step and watch the sum update without recounting.

window sum = ?  ·  best so far = ?
The lit lockers are the current window. Each slide does one add and one subtract, no matter how wide the window is. That's the trick.
Two flavours of window A fixed window (like this one) stays the same width and just slides. A variable window grows its right edge to include more, then shrinks its left edge when a rule breaks (for example "no repeated letters"). Same idea, both edges are just pointers moving forward, never backward.
Quick check
A window of width 500 slides one step right. How much work to get the new sum?
ExactlyThe two windows share 499 of their 500 values. Only one enters and one leaves, so it's one add and one subtract, O(1) per slide. That's what turns O(n × k) into O(n).
The old and new windows overlap almost entirely. How many values actually change when you slide by one? Try again.
✦ Bonus · go deeper, optional

Still curious? Keep asking why

Optional. Press why? to open each reason.

Two pointers and sliding window are secretly the same idea.

Both keep two markers into the array and move them so that every element is visited a constant number of times, and neither marker ever goes backward. Converging two pointers move toward each other; a sliding window moves both forward. The shared promise is the same: one pass, O(n), no re-scanning.

A variable window can shrink and grow, yet still be O(n).

It feels like cheating: the left edge sometimes jumps forward several times in a row. But across the whole run, the left edge can only move forward a total of n times, and so can the right. Two markers, each advancing at most n steps, means at most 2n moves total. Still one pass.

Sorting first can be worth it, even though sorting costs O(n log n).

If a problem is naturally O(n²) and sorting unlocks a clean O(n) two-pointer pass, your total becomes O(n log n) for the sort plus O(n) for the scan, which is O(n log n) overall. That's a huge win over O(n²). Recognising "if this were sorted, two pointers would work" is a real interview skill.

5 Where it hurts · when these don't apply

Powerful, but not universal

These techniques are sharp tools for the right job and useless for the wrong one. Knowing when not to reach for them is half the skill.

Two pointers needs order

Converging pointers only work when moving a pointer reliably changes the answer one way, which usually means the data is sorted. On unsorted data, a pointer move tells you nothing.

Windows need a "monotone" rule

A sliding window works when growing the window makes a quantity only go up (like a sum of positives) so shrinking can fix it. With negative numbers, "window sum" stops behaving, and you need a different idea (prefix sums, Arc 3).

Not for "any pair anywhere"

If a problem needs pairs that aren't about order or contiguity, two pointers won't reach them. That's often a signal for a hash map instead.
🔑
The reflex to buildWhen you see "pair that sums to X" on sorted data, think two pointers. When you see "best contiguous stretch" or "longest substring with a rule", think sliding window. Naming the pattern fast is most of the battle.
6 Daily life · where these hide

Where two pointers and windows show up

Merging two sorted lists

Your music app merging two sorted playlists walks both with a pointer each, always taking the smaller next. That's two pointers on two lists.

Video buffering

A player keeps a window of "seconds around now" loaded, sliding it forward as you watch and dropping what's behind.

Rate limits

"No more than 100 requests in any 60-second window" is literally a sliding window over timestamps.

Analytics

"Best 7-day stretch of sales" or "rolling average" are windows sliding across a row of daily numbers.

Text selection

Finding the shortest snippet that contains all your search words is a classic variable window over the document.

Networking

TCP's "sliding window" controls how much data is in flight at once. Same name, same idea, at the heart of the internet.

7 Practice · think first

Name the technique before you code

Three situations. For each, the first question is always the same: is this a pair-on-sorted problem (two pointers) or a best-contiguous-stretch problem (sliding window)? Hints lead, they don't tell.

Problem 1 · warm-up
A fitness app has a sorted list of workout durations. A user wants two sessions that add up to exactly 60 minutes. Find such a pair, fast.
Lead your own thinking
Hint 1 · what's the shape?A pair that sums to a target, on a list that's already sorted. Which of today's two tools fits "pair" plus "sorted"?
Hint 2 · set up the pointersWhere do you start left and right so their sum is as small and as large as possible?
Hint 3 · the decisionSum too big, move which pointer? Too small, move which? When do you stop?
Discussion

"Pair" plus "sorted" is the two-pointer flag. Left at the start, right at the end. Sum too big, step right down. Too small, step left up. Equal, you found it. Stop when the pointers meet. O(n), and it only works because the list is sorted. Recognising the shape is the whole solve. The code is five lines.

Problem 2 · the window
A trading app wants the highest total over any 5 consecutive days from a long list of daily profits. It currently re-adds all 5 numbers for every starting day and it's too slow.
Lead your own thinking
Hint 1 · what's the shape?"Best total over any 5 consecutive days" is a best-contiguous-stretch problem. Which tool?
Hint 2 · the wasteWhen you move from days 1-5 to days 2-6, how many of the numbers are the same? How many actually change?
Hint 3 · the updateInstead of re-adding 5 numbers, what single add and single subtract turns the old sum into the new one?
Hint 4 · track the bestAs the window slides across, what do you keep updating so you can report the answer at the end?
Discussion

Fixed sliding window. Add the first 5 once. Then for each slide, add the entering day and subtract the leaving day, keeping a running max. Each slide is O(1), so the whole thing is O(n) instead of O(n × 5). The overlap between neighbouring windows is the waste you delete.

Problem 3 · the growing-and-shrinking window
A messaging app highlights the longest run of recent messages with no repeated word. The run can be any length. Find the length of the longest stretch with all-distinct words.
Lead your own thinking
Hint 1 · fixed or variable?The stretch can be any length, so the window width isn't fixed. What kind of window grows and shrinks?
Hint 2 · grow the rightKeep extending the right edge, adding one word at a time. What do you need to remember to detect a repeat?
Hint 3 · shrink the leftThe moment a repeat appears inside the window, how do you move the left edge to make the window valid again?
Hint 4 · the recordAfter every step, what do you compare against your best-so-far length?
Discussion

Variable window. Grow the right edge and remember where you last saw each word. When the incoming word is already inside the window, jump the left edge just past that earlier copy, so the window has no repeats again. Track the largest width you ever reached. Both edges only move forward, so it's O(n). Grow to include, shrink to obey the rule. This is the exact problem foreshadowed back in Module 1.

8 Now code it · C++, interview-style

Easy · two pointersLeetCode 167 · Two Sum II (sorted input)

Given a sorted array and a target, return the 1-based positions of the two numbers that add up to the target. Exactly one answer exists.

Example: [2,7,11,15], target 9 → [1,2] (2 + 7 = 9)

Step 1 · Understand it

Input: a sorted array and a target sum. Output: the two positions (counting from 1) whose values add up to the target. We're promised exactly one pair exists, so we don't have to handle "no answer".

Step 2 · Brute force first

Two nested loops: for each value, check it against every value after it. It works and it's easy. But it's O(n²), and it throws away the fact that the array is sorted. That wasted gift is our clue.

Step 3 · Find the waste

Put left at the start and right at the end. If their sum is too big, only the right value can shrink it, so step right down. If too small, step left up. Each comparison eliminates a whole row of pairs the brute force would have checked. One pass, O(n).

Step 4 · Pseudo-code it
Pseudo-code · converging pointers
left = 0, right = last index
while left < right:
    sum = nums[left] + nums[right]
    if sum == target: return (left+1, right+1)
    if sum < target: left = left + 1
    else: right = right - 1
Step 5 · Code it, then cost it
C++
vector<int> twoSum(vector<int>& nums, int target) {
    int left = 0, right = nums.size() - 1;
    while (left < right) {
        int sum = nums[left] + nums[right];
        if (sum == target) return {left + 1, right + 1};
        if (sum < target) left++;
        else right--;
    }
    return {};
}

Time: O(n), the pointers meet after one pass. Space: O(1), just two indices.

Connects to: the exact same converging-pointer move as the demo above, and the reverse-in-place from Module 1.

Medium · sliding windowLeetCode 3 · Longest Substring Without Repeating Characters

Return the length of the longest run in a string that has no repeated character.

Example: "abcabcbb" → 3 (the run "abc")

Step 1 · Understand it

Find the longest contiguous stretch of characters where nothing repeats, and return its length. The stretch can be anywhere and any length. Edge case: an empty string gives 0.

Step 2 · Brute force first

Try every starting position, and from each, extend until you hit a repeat, checking each new stretch for duplicates. That's roughly O(n²) or worse. It re-examines the same characters over and over as the start moves.

Step 3 · Find the waste (variable window)

Keep one window and remember the last position where each character was seen. Extend the right edge one character at a time. If the new character was already seen inside the current window, jump the left edge to just past that earlier copy, which instantly removes the repeat. Track the widest the window ever gets. Both edges only move forward, so it's O(n).

Step 4 · Pseudo-code it
Pseudo-code · variable window
lastSeen = position of each character, start all as -1
left = 0, best = 0
for right from 0 to last:
    c = s[right]
    if lastSeen[c] >= left:
        left = lastSeen[c] + 1     // jump past the repeat
    lastSeen[c] = right
    best = max(best, right - left + 1)
return best
Step 5 · Code it, then cost it
C++
int lengthOfLongestSubstring(string s) {
    vector<int> lastSeen(128, -1);
    int left = 0, best = 0;
    for (int right = 0; right < s.size(); right++) {
        char c = s[right];
        if (lastSeen[c] >= left)
            left = lastSeen[c] + 1;
        lastSeen[c] = right;
        best = max(best, right - left + 1);
    }
    return best;
}

Time: O(n), each character enters and leaves the window once. Space: O(1), a fixed 128-slot table of last-seen positions.

Connects to: the "turn a character into an index" trick from Module 1, now powering the window. This is the problem Module 1 promised you'd solve here.
